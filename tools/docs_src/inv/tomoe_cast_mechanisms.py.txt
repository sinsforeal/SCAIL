DOCSTRING:
A person around her as a set of mechanisms rather than a description.

A character sheet says what somebody is like. A mechanism says what makes
them do a thing, what stops them, and what it buys them -- trigger,
suppressor, function -- so the model has something to run rather than an
adjective to perform. This is the same shape the extracted character
already uses (`docs/mechanism-codebook.md`); the difference is that these
are authored, not coded off a tape, so every one of them says so.

The file is `<cast.mechanisms_dir>/<roster key>.json`, one per person on the
roster, and a person with no file has no block: the calls go out exactly as
they did before. `docs/cast-mechanisms.md` is the spec.

Three things come out of a file and they do not go to the same places:

- a **mechanism** goes to the roles named in its own `readers`, and to no
  others. A mechanism nobody reads is DEAD, the way a gauge nothing acts on
  is DEAD (`tools/cast_mechanisms_test.py` names them).
- a **driver** is one short paragraph of what the person is after, rendered
  with the mechanisms it drives.
- a **secret** is what she knows and does not say, so it reaches her own
  mouth (`cast_turn`, `cast_beat`) and nowhere else: never the planner, who
  writes for everybody, and never another speaker's call.

What never reaches a prompt from here: the mechanism's id, its `name`
(a function phrase for humans), its `class` and `tier`. The personality type
each person was written from is not in this file and is not readable from
this module at all -- it lives in a file of the author's that only
`tools/cast_type_test.py` may open, because naming the type to a model would
be handing it the answer the measurement is asking for.
